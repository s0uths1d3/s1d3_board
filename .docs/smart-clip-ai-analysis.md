# 智能剪贴板 AI 分析策略

Ctrl+B 手动触发的 AI 分析（关键词 + 一句话总结）分流策略。核心原则：**本地优先、手动触发、成本护栏、技术内容不外发**——复制入库时仅本地切分与预判打标（零 AI 成本、静默），Ctrl+B 时按标签分流，只有值得分析的自然语言散文才发起 AI 调用；代码、JSON、SQL、命令行等技术工件与密钥/编码内容一律本地处理，绝不送 AI。

## 设计原则

- **手动触发即开关**：不设独立总开关，不按 Ctrl+B 就不消耗任何 token
- **本地打标先行**：预判全部为本地纯函数判定，微秒级，在复制入库时完成，Ctrl+B 等待时间即纯 AI 网络时间
- **技术内容不外发**：代码片段、JSON、SQL、shell 命令、配置、diff 等技术工件一律排除在 AI 分析之外（隐私 + 无总结价值双重理由），本地切分即是终点
- **单次调用双产出**：关键词与总结合并为一次 AI 请求，输入 token 只付一遍
- **失败永不污染**：AI 失败/解析失败不写缓存，修复配置后重按即真实重试
- **习惯数据不出域**：用户习惯仅本地采集存储；发往 AI 的只有确定性生成的统计摘要，不含任何剪贴板原文

## 触发与前置条件

Ctrl+B 按下后的完整流程：

```
1. AI 提供商未配置（无 provider/model） → 弹岛「请先配置 AI 提供商」，结束
2. 读取预判标签（复制时已打好；未打标则现场本地判定一次）
3. 按七级分流决策表执行：命中 1–6 级 → 本地结果 + 对应灵动岛提示，结束
4. 第 7 级散文 → 生成偏好摘要（含版本号）→ 发起 AI 单次调用（关键词 + 总结）
   → 沿用现有「AI 解析中 / 成功 / 失败」提示
```

与智能剪贴板三种模式的交互：

| 模式 | 交互 |
|---|---|
| `off` | AI 分析独立于切分模式，Ctrl+B 仍可触发（切分关闭不影响按需分析） |
| `auto` | autoSplit 结果即打标来源 |
| `scheme` | 与方案内 AI 提取器**并存**，缓存键独立（分析缓存键加独立前缀），互不命中 |

## 七级分流决策表

| 优先级 | 判定 | 本地处理 | 灵动岛提示 |
|---|---|---|---|
| 1 | 长度 > 上限（默认 1000 字） | autoSplit 照常切分，不送 AI | 内容超过 {n} 字，已跳过 AI 分析 |
| 2 | 命中结构层（JSON/链接/日志行/多行/分隔符；多行含误伤修正） | 本地切分结果 | 结构化内容，已本地切分 |
| 3 | 高熵内容（密钥/编码/哈希，覆盖率 > 60%） | 原文直通单段 | 编码或密钥内容，已跳过 AI 分析 |
| 4 | 技术工件（代码/SQL/命令/配置/diff，信号判定） | 本地切分结果 | 代码或技术内容，已跳过 AI 分析 |
| 5 | 数字/符号噪声（占比 > 80%） | 原文直通单段 | 内容无有效语义，已跳过 AI 分析 |
| 6 | 长度 < 20 字 | 本地结果 | 内容过短，无需 AI 分析 |
| 7 | 其余散文（20 字 ~ 上限） | AI 单次调用 | 沿用现有提示 |

预判顺序固定：结构层在前，高熵/技术工件/噪声为「散文层排污阀」依次排后，避免大段 base64、代码、纯数字串误入散文分支送 AI。多行代码会先被第 2 级 tryLines 拦下（提示「已本地切分」），单行代码落到第 4 级——两条路径殊途同归，均不送 AI。

## 预判信号详解

### 结构化判定

autoSplit 分层落点即判定结果，命中任一结构层即结构化：

| 层 | 内容形态 |
|---|---|
| tryJson | 顶层 JSON array/object（≥2 个元素/键值对） |
| tryLinks | 链接/邮箱 ≥2 个且覆盖率 ≥ 50% |
| tryLogLine | `[时间][来源][级别]` 日志行结构 |
| trySeparators | 分隔符竞标命中（制表符/竖线/逗号等，深度感知） |
| tryLines | ≥2 非空行——**含误伤修正，见下** |

**多行散文误伤修正**：分段散文（如一篇 800 字短文分 3 段）会被 tryLines 命中而永判结构化、错过 AI 分析。修正规则：多行命中且**平均行长 > 60 字**时视为散文段落，不判结构化（继续走后续判定）。短行列表（地址块、逐行字段、代码块）不受影响。

### 高熵判定（密钥/编码/哈希）

| 类型 | 信号 |
|---|---|
| 已知密钥前缀 | `sk-`、`ghp_`、`AKIA`、`AIza`、`xoxb-`、`eyJ`（JWT）等 |
| 哈希 | 纯十六进制，长度 32/40/64 |
| base64 | 连续 `[A-Za-z0-9+/=]` 串长度 > 40（含 data URI 的 base64 载荷） |
| 通用 token | 单个无空格 token > 32 字符且大小写数字混杂 |
| 赋值形态 | `api_key=…`、`Authorization: Bearer …`、`token: …` |

整段口径：高熵 token 对全文覆盖率 > 60% 判为高熵内容（优先级 3）。

**散文夹密钥的脱敏**：覆盖率 ≤ 60% 但检出**明确密钥形态**（前缀命中 / JWT / 赋值形态）时，内容按散文送 AI，但发送前把命中的 token 替换为 `[REDACTED]` 占位符——关键词与总结照常产出，密钥不外发第三方接口。

### 技术工件判定（代码/SQL/命令/配置/diff）

技术工件 = 以机器为主要读者的文本。判定信号（类型互异，**命中 ≥2 类**即判为技术工件）：

| 信号类 | 判据 |
|---|---|
| 语言关键词 | `function` `def` `class` `import` `const` `return` `void` `fn` `func`、SQL 的 `SELECT` `FROM` `WHERE` `INSERT` 等命中 ≥2 个 |
| 代码符号密度 | `{}()[];=<>/` 等符号占全文比例 > 15% |
| 缩进结构 | 行首空白/tab 的行占比 > 40% |
| 注释形态 | `//`、`/*`、行首 `#`、`<!--` 出现 |
| 代码围栏 | ``` 围栏包裹 |
| diff/patch | 行首 `+` / `-` / `@@` 结构出现 |
| shell 命令 | `$` 引导、或 `sudo` `git` `npm` `pip` `docker` `curl` 等词引导行 |
| 标签结构 | `<tag>…</tag>` 形态（HTML/XML/JSX）密度高 |
| 调用/赋值链 | `x.y(`、`foo(bar)` 括号调用模式密度高 |

设计取舍：阈值取「2 类互异信号」而非单信号，避免误伤含少量括号/引号的正常散文；Markdown 正文引用代码块（围栏内小段）整体仍按技术工件拦截，符合「技术内容不外发」原则。

### 噪声与长度判定

- **数字/符号噪声**：数字与标点占全文比例 > 80%（如 `123 456 789`、纯符号行）→ 无语义，不送 AI
- **长度上限**：KV `ai_analysis_max_chars`，默认 1000，设置页钳制范围 100–10000，非法输入（非数字/越界/空）回落默认 1000；边界「恰好等于上限」视为未超长
- **长度下限**：20 字固定（恰好 20 字可送 AI）；空内容/纯空白经 sanitize 后为空 → 归入下限拦截

## 用户习惯体系与交换协议

用户习惯数据**仅存本地 db**；与 AI 分析的交互遵循本章定义的标准交换协议：单向注入、统计摘要、确定性生成、版本化失效。

### 采集范围

| 信号 | 来源 | 说明 |
|---|---|---|
| 粘贴次数 × 提取器 | 现有 habit 表 | 哪些提取器的产出被实际粘贴 |
| 粘贴长度分布 | 粘贴行为 | 短（<10 字）/ 中（10–50）/ 长（>50）三档计数 |
| 粘贴类型分布 | 粘贴行为 | 链接 / 纯文本 / 数字 / 代码（按产出 source/extractorId 归类） |
| 语言分布 | 粘贴行为 | 中文 / 英文 / 其他 |
| AI 采纳反馈 | AI 分析产出 | 展示的关键词中被用户粘贴的数量（核心反馈信号，决定偏好调节方向） |

工作流类信号（粘贴序列模式、时段规律）为二期预留，一期不采集。

### 数据格式（本地存储 schema）

存储：db 表或 KV `ai_habit_profile`，单对象 JSON：

```json
{
  "version": 3,
  "pasteLengthDist": { "short": 42, "medium": 17, "long": 5 },
  "pasteTypeDist": { "link": 20, "text": 30, "number": 11, "code": 3 },
  "pasteLangDist": { "zh": 40, "en": 24 },
  "aiAdoption": { "shown": 30, "pasted": 12 },
  "topExtractors": [ { "id": "url", "count": 25 } ],
  "updatedAt": 1758000000000
}
```

- `version`：schema 结构版本，解析不认识的高版本按无数据处理
- `updatedAt`：最近更新时间戳
- 计数器只增不减，历史无衰减（二期可加时间窗衰减）

### 标准交换协议（习惯 → AI）

**单向数据流**：本地习惯数据 →（确定性生成）→ 偏好摘要文本 → 注入 AI 分析 prompt。AI 不回写任何数据，产出采纳与否由本地粘贴行为回填 `aiAdoption`。

**确定性生成规则**（同一数据必产出同一摘要，保证缓存键稳定）：

1. 各分布按总数归一化为百分比，四舍五入取整
2. 仅保留占比 ≥ 5% 的项，其余归入「其他」
3. `topExtractors` 截取前 3
4. 采纳率 `pasted/shown` 分档映射为粒度指令：

| 采纳率 | 注入指令 |
|---|---|
| < 20% | 关键词更短更精（3 个以内，偏术语） |
| 20%–50% | 关键词适中（最多 5 个） |
| > 50% | 关键词可更完整（保留短语形态） |

5. 采纳样本 < 10 次时不生成粒度指令（数据不足，用中性默认）

**注入模板**（偏好段拼接在分析指令之后，总长 ≤ 300 字符，超限按上述规则逐项裁剪）：

```
[用户偏好摘要 / User preference digest]
- 粘贴长度偏好：短 65% / 中 25% / 长 10%
- 粘贴类型偏好：纯文本 50%、链接 35%、数字 15%
- 语言偏好：中文 62%、英文 38%
- 关键词粒度：适中（最多 5 个）
```

**降级规则**：

| 场景 | 行为 |
|---|---|
| 新用户 / 粘贴记录 < 10 条 | 不注入偏好段，prompt 用中性模板 |
| 某分布数据为空 | 该行省略，不输出 0% 项 |
| 摘要生成本身异常 | 静默降级为中性模板，分析照常发起 |

**隐私边界**：摘要只含统计数字与档位描述，不含任何剪贴板原文、密钥、内容片段；原始行为数据永不离开本地 db。

**版本化失效**：偏好摘要生成时取当前习惯数据版本号（计数变更即 +1，粗粒度）写入缓存键；习惯变化后旧缓存自然失效，下次分析按新偏好重新生成。

## AI 调用规范

单次请求，输出 JSON（解析失败 = 本次分析失败）：

```json
{ "keywords": ["最多 5 个关键词"], "summary": "一句话总结" }
```

| 规则 | 行为 |
|---|---|
| 输出语言 | 跟随内容主语言（指令中明确要求，与 UI 语言无关） |
| keywords 超量 | 模型返回 > 5 个时截断取前 5 |
| 产出校验 | keywords 为空数组**且** summary 为空 → 视为失败，不写缓存、弹失败提示 |
| summary 长度 | 存储不截断，气泡窗口展示层截断 |
| 请求超时 | 15 秒（沿用现有） |
| prompt 结构 | 分析指令 → 输出契约（沿用 OUTPUT_CONTRACT 风格）→ 偏好摘要段（可降级省略） |

## 缓存与并发

| 机制 | 行为 |
|---|---|
| 缓存键 | 分析前缀 + 内容 hash + 偏好摘要版本号，与方案 AI 提取器缓存键隔离 |
| 冷却窗口 | 沿用 `ai_cache` 300 秒 |
| 飞行中去重 | 等待期连按 Ctrl+B 共享同一请求，不重复消耗 token（沿用现有机制） |
| 失败 | 不缓存（超时/非 2xx/JSON 解析失败/产出为空一律），下次按即真实重试 |
| 快路径 | 缓存命中返回 < 400ms 时不弹「AI 解析中」，直接展示结果（沿用现有行为） |

## 灵动岛提示汇总（i18n）

| key | 中文 | 英文 |
|---|---|---|
| `island.aiNotConfigured` | 请先配置 AI 提供商 | Configure an AI provider first |
| `island.aiSkippedLong` | 内容超过 {n} 字，已跳过 AI 分析 | Content exceeds {n} chars; AI analysis skipped |
| `island.aiSkippedStructured` | 结构化内容，已本地切分 | Structured content; split locally |
| `island.aiSkippedEncoded` | 编码或密钥内容，已跳过 AI 分析 | Encoded content or secret; AI analysis skipped |
| `island.aiSkippedTech` | 代码或技术内容，已跳过 AI 分析 | Code or technical content; AI analysis skipped |
| `island.aiSkippedNoise` | 内容无有效语义，已跳过 AI 分析 | Content has no semantic value; AI analysis skipped |
| `island.aiSkippedShort` | 内容过短，无需 AI 分析 | Content too short for AI analysis |

提示时机统一为 **Ctrl+B 按下后**（分流结果反馈），复制入库时静默不弹岛。同内容连按命中缓存时依赖 bubble.vue 既有 5 秒窗口重复计数徽标，不叠加弹窗。

## 边界情况速查

| 场景 | 判定与处理 |
|---|---|
| 空内容 / 纯空白 | sanitize 后为空 → 单段原文，Ctrl+B 归入过短拦截 |
| 单个 URL（< 20 字） | 过短拦截，本地单段（复制 URL 本就为整段粘贴） |
| 大段 base64 / data URI | 覆盖率超 60% → 高熵拦截；且大概率同时超长，双重保险 |
| 散文中夹一个 API key | 覆盖率 ≤ 60% → 按散文送 AI，密钥 token 发送前脱敏为 `[REDACTED]` |
| 单行短代码（≥ 20 字） | 技术工件判定拦截（关键词/符号/调用链信号），本地切分 |
| 多行代码块 | tryLines 先命中 → 本地逐行切分，提示「已本地切分」 |
| SQL / shell 命令 / YAML 配置 | 技术工件判定拦截 |
| git diff / 补丁 | diff 信号 + 行结构命中 → 技术工件拦截 |
| Markdown 正文含小段围栏代码 | 围栏信号命中 → 技术工件拦截（技术内容不外发） |
| 分段散文（多行长段落） | 平均行长 > 60 字 → 不判结构化，正常送 AI |
| 短行列表（地址/字段） | 多行判定照常命中，本地切分 |
| 纯数字串 / 符号堆 | 噪声占比 > 80% → 不送 AI，原文直通 |
| 中英混排散文 | 送 AI，输出语言跟随内容主语言 |
| JSON 但仅 1 个元素 | tryJson 要求 ≥2 不命中 → 落后续层；若含代码信号由技术工件层拦截 |
| 散文 + 偶发括号/引号 | 技术工件需 ≥2 类互异信号，不误伤 |
| AI 未配置 | 弹岛「请先配置 AI 提供商」，不发起任何请求 |
| 自定义提供商配置错误 | 请求失败 → 弹失败提示，不缓存，修复后重按即重试 |
| 新用户首次分析 | 无偏好数据 → 中性模板，分析照常 |
