## 一、富文本保留（✅ 已实现）

### 功能说明

从浏览器、Word、飞书等应用复制带格式内容时，剪贴板会同时写入纯文本与 HTML 两种格式。本功能将 **HTML 源码一并保留**：历史列表中该条目以「富文本」类型记录，粘贴到支持 HTML 的目标应用（如 Word、邮件客户端、飞书文档）时**还原加粗、字体、颜色、表格、链接等格式**；粘贴到纯文本目标（如记事本、代码编辑器）时自动降级为纯文本。

### 技术实现方案

- **监听端**（[clipboardListener.ts](../app/src/clipboard/clipboardListener.ts)）：`onTextUpdate` 回调内先 `hasHTML()` 探测、再 `readHtml()` 读取。Windows 剪贴板的 HTML 格式可能携带 CF_HTML 框架注释（`<!--StartFragment-->…<!--EndFragment-->`），读取后用正则裁出真实片段再入库；读取失败回退纯文本条目，行为不劣化。
- **数据模型**（[migrations.rs](../src-tauri/src/db/migrations.rs) v18 / [migrator.ts](../app/src/core/db/migrator.ts) 双侧兜底）：`clipboard` 表新增 `html_content TEXT` 列，`type` 列的 CHECK 约束（原仅允许 `text`/`image`）通过**标准表重建流程**放宽为四种类型（SQLite 不支持 DROP CONSTRAINT）。
- **类型体系**：条目 `type` 扩展为 `'text' | 'image' | 'html' | 'files'`（[entities.ts](../app/src/entities.ts)）。`html` 条目 `content` 存纯文本兜底（列表/搜索/tooltip 全链路按纯文本工作），`html_content` 单独存 HTML 源码。
- **搜索**：仅文本筛选与全量搜索的 SQL 条件由 `type = 'text'` 改为 `type IN ('text', 'html')`，富文本条目按纯文本内容命中。
- **粘贴还原**（[pasteUtil.ts](../app/src/commands/local/pasteUtil.ts)）：`html` 类型走 `writeHtmlAndText(html, text)` 双格式写入，目标应用按能力择优。
- **统计**：富文本条目计入「复制文本次数」与「打字量」（字符数按纯文本兜底计）。

### 操作指南

1. 正常复制（`Ctrl+C`）任何带格式的内容，历史列表自动出现「富文本」类型条目（信息行类型显示为「富文本」）。
2. 双击列表行或按 `Enter` 粘贴：支持格式的目标应用（Word/邮件/飞书）还原原始格式，记事本等得到纯文本。
3. 右键「复制」：同样以 HTML + 纯文本双格式写回系统剪贴板。
4. 搜索：与普通文本一致，按内容命中。

### 边界说明

- 常用剪贴板（Pinned）收藏富文本条目时按**纯文本兜底**保存（常用剪贴不保存 HTML 源码）。
- 部分应用复制的 HTML 与纯文本完全等价（如终端），此时仍按富文本入库，粘贴行为无感知差异。

### 相关设置

本功能为**自动行为，无独立开关**：复制带格式内容即记录为富文本。富文本条目与普通文本条目共享全部剪贴板设置（历史保留时间、忽略的应用等约束一致生效）。

## 二、文件复制支持（✅ 已实现）

### 功能说明

在资源管理器中复制一个或多个文件/文件夹后，剪贴板历史会记录为「文件」类型条目（显示文件名序列与「N 个文件」徽章）。粘贴时**还原完整的 CF_HDROP 文件语义**——目标资源管理器窗口执行粘贴即复制这些文件，与系统原生复制文件行为一致。

### 技术实现方案

- **监听端**（[clipboardListener.ts](../app/src/clipboard/clipboardListener.ts)）：`startListening` 增加 `files: true` 监听类型；`onSomethingUpdate` 回调中 `updated.files` 分支调用插件内置 `readFiles()`（Rust 侧解析 CF_HDROP 得到绝对路径数组），`content` 存 `JSON.stringify(paths)`，`type='files'`。复制文件不携带 `CF_UNICODETEXT`，不会与文本条目重复记录。
- **展示**（[index.vue](../app/pages/index.vue)）：列表渲染文件名序列（`clipFilesPreview` 解析 JSON 取各路径尾段文件名）；信息行显示「N 个文件」徽章；tooltip 展示文件名序列。
- **粘贴还原**（[pasteUtil.ts](../app/src/commands/local/pasteUtil.ts)）：`files` 类型解析 JSON 后调用 `writeFiles(paths)` 写回系统剪贴板，再模拟 `Ctrl+V`——目标应用收到的是真正的文件拖放语义。
- **灵动岛**（[useCopyIsland.ts](../app/composables/useCopyIsland.ts)）：复制文件时岛胶囊展示文件名序列（而非 JSON 原串）。
- **统计**：文件条目计入「复制文本次数」（不计打字量字符数）。

### 操作指南

1. 在资源管理器选中文件/文件夹 → `Ctrl+C`，历史列表出现「N 个文件」条目。
2. 唤出剪贴板（`Ctrl+I`）→ 选中该条目 → `Enter` 粘贴：回到目标文件夹 `Ctrl+V` 即复制出这些文件。
3. 右键「复制」：将路径列表重新写回系统剪贴板（还原文件语义）。

### 边界说明

- 文件条目**不能**添加到常用剪贴板（常用剪贴粘贴通道只支持文本/图片）。
- 从应用拖出文件条目仅携带纯文本路径列表（WebView 无法还原拖放文件语义）。

### 相关设置

本功能为**自动行为，无独立开关**：复制文件即记录。文件条目同样受全局约束——被「忽略的应用」中复制的文件不记录；超期文件条目随「历史保留时间」清理（文件条目无原图文件，仅删记录）。

## 三、来源应用忽略记录（✅ 已实现）

### 功能说明

可指定某些应用「复制的内容不进入剪贴板历史」——被忽略应用中的一切复制行为（文本/图片/文件）不落库、不弹灵动岛。典型场景：密码管理器、即时通讯工具等不希望记录复制痕迹的应用。

**默认列表直接读取当前已配置的应用清单**（即此前复制过内容、已被记录来源的应用），点选即加入/移出忽略名单；也支持手动输入进程名添加（覆盖未运行过的应用）。

### 技术实现方案

- **存储**：KV 键 `ignored_apps`（JSON 字符串数组，[useIgnoredApps.ts](../app/composables/useIgnoredApps.ts)），小写比较匹配。
- **默认列表**：新增仓储方法 `fetchDistinctSourceApps()`（[clipboardRepository.ts](../app/src/core/db/repositories/clipboardRepository.ts)）——`SELECT source_app, COUNT(*) … GROUP BY … ORDER BY cnt DESC` 全量去重列出已记录的来源应用及条目数。
- **拦截点**（[clipboardListener.ts](../app/src/clipboard/clipboardListener.ts)）：文本/图片/文件三条监听路径均在落库前 `queryForegroundApp()` 查询前台进程名，命中 `isIgnoredApp()` 即静默返回（不落库、不弹岛）。
- **设置 UI**（[SettingMain.vue](../app/components/setting/SettingMain.vue)）：隐私设置组新增「忽略的应用」管理面板——上方手动输入框（可增删 chips），下方「已记录的应用」列表（带复制条数徽章，点选切换忽略状态，已忽略项带 ✓）。

### 操作指南

1. 打开设置 → 隐私 → **忽略的应用**，点击「管理」展开面板。
2. 「已记录的应用」列表即默认清单（此前复制过内容的应用，按条数排序）：点击应用即加入忽略（出现 ✓），再次点击取消。
3. 未运行过的应用：在输入框输入进程名（如 `keepassxc`，不区分大小写）回车添加。
4. 生效即时：被忽略应用中的复制不再出现在历史列表与灵动岛。

### 相关设置

| 设置项 | 存储键 | 说明 |
|--------|--------|------|
| 忽略的应用 | `ignored_apps` | 设置 → 隐私 → 忽略的应用；默认列出已记录的来源应用（按复制条数排序），点选切换忽略状态，支持手动输入进程名；变更即时生效 |

## 四、按时间过期策略（✅ 已实现）

### 功能说明

可设置剪贴板历史保留天数（7/30/90/365 天或永久），超期条目在**应用启动时**与**设置变更时**自动清理，图片条目联动删除原图文件。收藏条目（⭐）豁免清理。

### 技术实现方案

- **设置项**：KV 键 `clip_retention_days`（空串/0/无效 = 永久保留）。
- **清理实现**（`purgeExpiredClips`，[clipboardRepository.ts](../app/src/core/db/repositories/clipboardRepository.ts)）：`cutoff = now - days × 86400000`，删除 `WHERE is_favorite <> 1 AND created_at < cutoff`（收藏豁免与上限裁剪同语义）；500 条/批删除；`type='image'` 条目联动 `deleteImageFileByRef` 删原图。早期 TEXT 格式 `created_at` 存量行在 SQLite 类型序中恒大于数字，天然豁免（漏删无害）。
- **触发点**：应用启动（[clipboard.module.ts](../app/src/modules/clipboard.module.ts) start 末尾 fire-and-forget）+ 设置页变更立即生效。
- **设置 UI**：剪贴板设置组新增「历史保留时间」下拉框（永久/7 天/30 天/90 天/365 天），切换后立即清理并弹岛反馈删除条数。

### 操作指南

1. 打开设置 → 剪贴板 → **历史保留时间**。
2. 选择保留天数（默认永久）；选择后立即清理超期条目，灵动岛提示「已清理 N 条超期条目」。
3. 收藏（⭐）的条目不会被过期清理删除。

### 相关设置

| 设置项 | 存储键 | 说明 |
|--------|--------|------|
| 历史保留时间 | `clip_retention_days` | 设置 → 剪贴板 → 历史保留时间；默认**永久**，可选 7 / 30 / 90 / 365 天；变更后立即清理并弹岛反馈删除条数 |

## 五、常用剪贴板标签（✅ 已实现）

### 功能说明

常用剪贴板（Pinned）条目支持添加**标签**（逗号分隔的关键字），编辑器内填写，卡片上常驻展示——便于管理大量常用片段（如区分「工作」「个人」「代码模板」）。

### 技术实现方案

- **数据模型**：`pinned_clip` 表新增 `tags TEXT`（标签存 JSON 字符串数组）。
- **仓储**（[pinnedClipRepository.ts](../app/src/core/db/repositories/pinnedClipRepository.ts)）：`updatePinnedClip` 扩展 `tags` 可选参数，动态 SET 构建（`undefined` = 保持原值，`null` = 清空）。
- **编辑器**（[PinnedClipList.vue](../app/components/pinned/PinnedClipList.vue)）：编辑态新增标签输入框（**空格分隔**、兼容逗号、去空去重）；查看态标签以金色弱化徽章展示。脏检查（`isDirty`）涵盖标签，未保存关闭有确认。

### 操作指南

1. 切换到**常用剪贴板** Tab，鼠标悬浮条目点击「编辑」（或双击进入编辑态）。
2. 标签框输入以空格分隔的多个标签（如 `工作 周报`）。
3. 点击保存后：标签显示为条目上的徽章。

### 相关设置

标签为**条目级字段**（编辑器内逐条填写，随条目持久化），无全局设置项。

## 六、序列粘贴（✅ 已实现）

### 功能说明

将多个历史条目按**用户点选顺序**组成队列后，每次 `Enter` 自动粘贴队列中的下一条（循环步进），灵动岛显示进度（`序列粘贴 i/n`）。典型场景：连续填写多个表单字段（姓名 → 电话 → 邮箱…），无需每次回列表切换选中项。

### 技术实现方案

- **队列状态**（[clipboardStore.ts](../app/src/commands/local/clipboardStore.ts)）：`sequenceQueueIds`（id 数组，Set 插入序 = 点选顺序）+ `sequenceCursor`（游标，循环取模步进）。状态放共享 store——`index.vue` 与 `PasteCommand` 命中同一实例。
- **入队**：批量多选（`Ctrl`/`Shift` 点选）≥ 2 条后，批量工具栏出现「设为序列粘贴队列」按钮。
- **步进粘贴**（[PasteCommand.ts](../app/src/commands/local/PasteCommand.ts)）：序列模式激活时 `Enter` 忽略当前选中行，按游标取队列条目粘贴（加密条目自动解密、显式计数防双计），粘贴后 700ms 弹岛进度（延迟到「已粘贴」胶囊之后，岛单窗覆盖展示）。
- **容错**：队列条目被删除/裁剪后不在加载数据中时自动退出序列模式，防止粘贴错误内容。
- **退出**：批量选择清空后显示「序列粘贴中」状态条，点击「退出序列模式」结束。

### 操作指南

1. `Ctrl`（逐条）或 `Shift`（范围）多选 ≥ 2 条历史条目——**点选顺序即粘贴顺序**。
2. 批量工具栏点击「设为序列粘贴队列」，灵动岛提示就绪（N 条）。
3. 到目标输入框按 `Enter`（应用内唤出剪贴板后）：粘贴第 1 条；切到下一处再 `Enter`：粘贴第 2 条……队列用完自动回到第 1 条（循环）。
4. 每次粘贴后灵动岛显示进度 `序列粘贴 i/n`；回到应用点击「退出序列模式」结束。

### 相关设置

序列粘贴为**会话级功能，无全局设置**：队列由批量工具栏「设为序列粘贴队列」入口创建，退出走状态条按钮或清空批量选择；未激活时对普通粘贴行为零影响，队列不持久化（重启后自动失效）。

## 七、敏感条目落盘加密（✅ 已实现）

### 功能说明

对任意**文本**历史条目可开启「加密存储」：数据库中的内容替换为密文（AES-256-GCM），列表界面不再回显明文（锁形占位），tooltip/拖拽/批量复制等所有旁路同样不泄露明文；粘贴时自动解密。加密密钥保存在**操作系统凭据库**（Windows Credential Manager），不落 SQLite。

### 技术实现方案

- **加密原语**（[secure.rs](../src-tauri/src/commands/secure.rs)）：
  - 算法：AES-256-GCM（`aes-gcm 0.10`），每次加密随机 12 字节 nonce，AAD 绑定 `"S1d3Board-clip"` 防载荷移植。
  - 载荷格式：`S1ENC1:` 前缀 + base64(nonce ‖ 密文含 16 字节 tag)——前缀同时作为**明文/密文判别哨兵**（`isEncryptedContent`）。
  - 密钥管理：`keyring` get-or-create（服务名 `S1d3Board` / 用户 `clip_secret`，32 字节 hex），密钥永不出 Rust 进程；解密通过 `decrypt_clip_text` 命令完成。
- **切换实现**（`setClipboardEncrypted`，[clipboardRepository.ts](../app/src/core/db/repositories/clipboardRepository.ts)）：仅 `type='text'` 条目可加密（其他类型抛错）；加密时 `content` 原地替换为载荷、`encrypted=1`、明文派生列（`html_content`/`qr_text`）置 NULL；解除时解密回明文、`encrypted=0`。幂等：已处于目标状态直接返回。
- **UI 集成**（[index.vue](../app/pages/index.vue)）：
  - 右键菜单：文本条目出现「加密存储 / 解除加密」（按当前状态切换文案）。
  - 列表渲染：`encrypted=1` 条目内容区显示锁形「已加密条目」占位 + 信息行「已加密」徽章。
  - 明文防泄露旁路：tooltip 独立窗口不出加密条目预览；拖拽置空载荷；右键复制先解密再写；批量复制逐条解密合并（解密失败的密文条目剔除，不进剪贴板）；添加到常用剪贴板被拦截。
- **粘贴解密**（[PasteCommand.ts](../app/src/commands/local/PasteCommand.ts) / [ClipboardSlotPasteCommand.ts](../app/src/commands/local/ClipboardSlotPasteCommand.ts)）：粘贴前按 `S1ENC1:` 前缀判定，先 `decrypt_clip_text` 解密为明文再写剪贴板；解密失败（凭据库不可用/密钥不符）中止粘贴。
- **统计一致性**：永久抹除（purge）加密条目时跳过「字符计数回冲」（密文长度 ≠ 明文长度，宁可多计不错扣）。

### 操作指南

1. 右键任意文本条目 → **加密存储**：内容立即变为锁形占位，数据库落盘为密文。
2. 粘贴：`Enter` / `Ctrl+数字` / 右键复制均自动解密为明文，使用无感。
3. 右键已加密条目 → **解除加密**：恢复明文存储与列表显示。
4. 密钥在系统凭据库中（Windows：控制面板 → 凭据管理器 → Windows 凭据 → `S1d3Board`）；卸载应用不清除密钥，重装后仍可解密历史数据。

### 边界说明（如实标注）

- 加密范围为**文本条目**（图片/文件/富文本条目无加密入口）；富文本条目本身不加密。
- 密文存于本地 SQLite，密钥存于 OS 凭据库——二者同机共存时防「直接读库泄露明文」；**不能**防拥有系统登录权限的本地攻击者。
- 加密条目不参与全文搜索（搜密文无意义）；智能剪贴板解析管道对密文不生效。

### 相关设置

加密为**条目级操作**（右键菜单逐条开关），无全局设置项；无应用内密钥管理界面。密钥的存取位置由 OS 凭据库决定（Windows：控制面板 → 凭据管理器 → Windows 凭据 → `S1d3Board`），卸载应用不清除密钥。

## 设置项一览

本轮功能涉及的全局设置共两项，均为 KV 持久化、变更即时生效：

| 设置项 | 存储键 | 所属功能 | 设置入口 | 默认值 | 可选值 |
|--------|--------|----------|----------|--------|--------|
| 历史保留时间 | `clip_retention_days` | 按时间过期策略 | 设置 → 剪贴板 → 历史保留时间 | 永久 | 永久 / 7 天 / 30 天 / 90 天 / 365 天 |
| 忽略的应用 | `ignored_apps` | 来源应用忽略记录 | 设置 → 隐私 → 忽略的应用 | 空（不忽略任何应用） | 进程名列表（点选已记录应用 / 手动输入） |

其余功能为**自动行为或条目级操作**，刻意不设全局开关（零配置可用）：

| 功能 | 形态 | 配置方式 |
|------|------|----------|
| 富文本保留 | 自动 | 复制带格式内容即记录，无开关 |
| 文件复制支持 | 自动 | 复制文件即记录，无开关 |
| 常用剪贴板标签 | 条目级 | 常用剪贴编辑器内逐条填写 |
| 序列粘贴 | 会话级 | 批量工具栏入口创建队列，退出即结束，不持久化 |
| 敏感条目落盘加密 | 条目级 | 右键菜单逐条加解密，密钥存 OS 凭据库 |

## 未实现项

以下三项经差距分析识别后，**明确决策不实现**（需求优先级 / 技术成本考量），本文档如实标注：

### 1. 图片 OCR 提取文字 — ❌ 未实现

- **现状**：图片条目仅支持二维码识别（`qr_text`）与缩略图预览，**不做通用 OCR 文字提取**。搜索图片条目时只按二维码识别结果命中。
- **原因**：高质量 OCR 需引入 Tesseract 等本地引擎（体积 +30MB、跨平台编译链复杂）或云 API（违背本地优先原则）；中文场景识别率与剪贴板图片（截图/表情包）的内容形态匹配度低，投入产出比不足。
- **替代方案**：复制图片中的文字请使用系统/输入法自带 OCR（如 Windows + V、微信截图 OCR），所得文本进入剪贴板后自然被本应用记录。

### 2. 历史条目直接编辑 — ❌ 未实现

- **现状**：历史列表条目**只读**——不能直接在剪贴板历史中修改文本内容；需要修改时应先粘贴到目标应用编辑后再复制，或在常用剪贴板中重建条目。
- **原因**：历史条目按 `content UNIQUE` 去重、被使用计数/来源/统计引用，原地编辑会破坏「复制行为不可变记录」的语义模型（统计、去重、灵动岛内容溯源均依赖原 content）；且编辑场景的低频性不足以支撑该复杂度。
- **替代方案**：常用剪贴板条目本身支持编辑（内容/名称/标签），高频修改需求请将条目收藏后维护。

### 3. 粘贴前处理规则 — ❌ 未实现

- **现状**：粘贴时按原始内容还原（文本/富文本/图片/文件），**没有**「粘贴前自动去空格 / 去换行 / 正则替换 / 大小写转换」等处理规则引擎。
- **原因**：规则配置 UI 与规则执行链路涉及粘贴时序改造（处理后的内容会污染剪贴板历史去重），当前高频诉求已被「序列粘贴」「常用剪贴板」覆盖。
- **替代方案**：需要格式处理时先粘贴到目标应用处理，或借助智能剪贴板的分段解析能力。

## 数据库迁移说明

本轮所有表结构变更收敛于**一次版本化迁移 v18**（[migrations.rs](../src-tauri/src/db/migrations.rs)），并在前端 [migrator.ts](../app/src/core/db/migrator.ts) 提供等价兜底（`PRAGMA` 检查补列/重建），保证旧库（含手动拷贝的库文件）升级无损：

| 变更 | 内容 |
|------|------|
| `clipboard` 表重建 | `type` CHECK 放宽为 `text/image/html/files`；新增 `html_content TEXT`；新增 `encrypted INTEGER NOT NULL DEFAULT 0`（SQLite 不支持 DROP CONSTRAINT，走标准「建新表 → 拷数据 → 删旧表 → 重命名 → 重建索引」流程，并校正 `sqlite_sequence`） |
| `pinned_clip` 加列 | `tags TEXT`（条目标签，JSON 字符串数组） |
